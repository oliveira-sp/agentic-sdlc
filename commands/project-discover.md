
description: Generate or refresh project context documentation for the current repository


You are executing the `/project-discover` command.

Your task is to inspect the current repository and generate or refresh a **project context document** at:

```
docs/project-context.md
```

This document provides stable repository understanding for AI agents before they execute development workflows.

It is **not** a replacement for existing documentation. It is a concise summary derived from the repository's own files and conventions.

The repository remains the source of truth.

# Discovery Phase

Inspect the repository and gather relevant information.

Use available tools to understand the project. Focus on documented facts and avoid unsupported assumptions.

Collect information from the following sources when available.

## Repository identity and structure

Inspect:

* Git repository metadata
* remote information
* current branch
* recent commits
* root directory contents
* important directory structure

Ignore generated directories and dependencies such as:

* `.git`
* `node_modules`
* `build`
* `dist`
* `.venv`
* `target`


## AI agent guidance

Inspect:

* `AGENTS.md`

Extract:

* AI behavior rules
* coding constraints
* prohibited actions
* validation requirements
* workflow instructions


## Project documentation

Inspect when available:

* `README.md`
* `CONTRIBUTING.md`
* `ARCHITECTURE.md`
* `DESIGN.md`
* `TESTING.md`

Extract:

* project purpose
* architecture information
* development workflow
* testing expectations
* engineering constraints


## Build and dependency configuration

Inspect relevant project files when present:

Examples:

* `package.json`
* `Cargo.toml`
* `pyproject.toml`
* `Makefile`
* `CMakeLists.txt`
* `build.gradle`
* `go.mod`
* `pom.xml`

Extract:

* languages
* frameworks
* build systems
* dependencies
* test commands


## GitLab context (if available)

If GitLab MCP or GitLab access is configured, inspect:

* project metadata
* issue templates
* merge request templates
* labels
* workflow conventions

Use this information only to understand project workflow conventions.

Do not:

* create issues
* modify GitLab objects
* change project settings

Capture conventions such as:

* Feature → Task → Merge Request relationships
* issue template expectations
* merge request requirements
* review practices


## Existing project context

If:

```
docs/project-context.md
```

already exists:

Read the existing document.

Generate an updated candidate.

Compare the existing version with the new version.

Show the user:

* added information
* removed information
* changed information

Do not replace the existing file without user confirmation.


# Generation Phase

Generate or update:

```
docs/project-context.md
```

Use this structure:

```markdown
# Project Context

> Generated by `/project-discover`.
> This document summarizes repository knowledge for AI-assisted workflows.
> The repository documentation and source code remain the source of truth.

## Project Overview

Describe the purpose of the project.

Summarize from:
- README
- documentation
- repository structure

## Technology Stack

Describe:
- languages
- frameworks
- build systems
- tooling

Only include information supported by repository evidence.

## Repository Structure

Describe important directories and their purpose.

Focus on:
- source directories
- test directories
- important modules
- configuration directories

## Architecture Overview

Describe the high-level architecture and design principles.

If architecture documentation does not exist, explicitly state that.

## Development Workflow

Describe how work is organized.

Include when discoverable:

- Feature → Task → Merge Request relationships
- branching strategy
- issue templates
- merge request expectations
- review practices

## Testing and Validation

Describe:

- testing frameworks
- validation commands
- CI checks

Include commands when they can be determined.

## Engineering Constraints

Describe important constraints:

Examples:
- coding standards
- supported platforms
- resource limitations
- compatibility requirements

If none are documented, state that.

## AI Agent Guidance

Summarize relevant instructions from:

- AGENTS.md
- CONTRIBUTING.md
- repository conventions

Focus on:

- required behaviors
- prohibited actions
- validation requirements
```



# Artifact Quality Rules

The generated document must:

* be concise
* remain below approximately 100 lines
* summarize instead of copying source documents
* contain only repository-supported information
* clearly separate facts from assumptions

Avoid statements like:

> "The project follows best practices"

unless explicitly documented.

Prefer:

> "The project uses CMake based on CMakeLists.txt."



# Artifact Ownership Rules

Remember:

* Human documentation is the source of truth.
* `docs/project-context.md` is an AI-oriented summary artifact.
* The artifact helps workflows understand the repository.
* The artifact does not replace architecture or contribution documentation.



# Completion Behavior

After generating the document, present a concise summary:

Include:

* what was discovered about the project
* where the document was written
* notable constraints or guidance discovered
* whether information was missing

Do not modify:

* source code
* build configuration
* GitLab objects
* `.opencode` configuration
* SDLC framework configuration

The only file created or modified by this command should be:

```
docs/project-context.md
```
